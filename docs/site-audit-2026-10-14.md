Это не доказательство корректности всех RLS-политик: для последнего нужны тестовые аккаунты разных ролей и отдельная матрица разрешений.

## Исправления визуала и профиля

- При начальном чтении показывается скелетон вместо временного имени «Путешественник» и нулевой статистики. Ошибка чтения имеет отдельное состояние и повтор запроса; сохранение не скрывает уже загруженный профиль.
- Настройки и редактор используют общие стеклянные карточки, компактные строки, скруглённые поля, одинаковые иконки и отступы. У редактора убрана вложенная прокрутка. `@` размещён внутри поля username, без отдельного прямоугольного сегмента.
- Две независимые колонки настроек убирают пустую область под карточкой приложения. На мобильном сохранён порядок: приложение → публичный профиль → управление → аккаунт.
- Устранена причина невозможности вводить пробел: очистка текста раньше выполняла trim при каждом нажатии. Ввод сохраняет пробелы и переносы, окончательная нормализация происходит при сохранении. Проверены последовательный ввод слов и переносы строк.
- Отмена редактора восстанавливает сохранённые значения. Настройки подтверждаются сервером и не остаются визуально сохранёнными при ошибке PATCH. Обновление аватара уведомляет общую шапку.
- Из ответа профиля убраны лишние данные и неиспользуемый запрос feedback. Одновременные чтения `/api/user/me` шапкой, сайдбаром и контролем доступа объединяются; результат проверяется по user ID и не кэшируется между аккаунтами.

## Планирование и зависание на 98%

Логи пользователя заканчиваются на сборе DynamicContext после проверки маршрута. Они не доказывают конкретную ошибку модели: ответа модели или завершения запроса в фрагменте нет. Число 98% раньше было пределом случайной анимации, поэтому по нему нельзя было определить реальный этап.

Исправлено:

- На `/plan` добавлен выключенный по умолчанию чекбокс выбора вайба. Без него генерация запускается сразу; с ним открывается `/plan/vibe`. Экономичный бюджет в обоих случаях проходит общий диалог уточнения.
- На вайб-странице сломанная внешняя картинка заменена существующим локальным изображением. Убраны неподтверждённые «точность 98.4%» на планировании и создании из рилса.
- Генератор показывает фактические этапы: подготовка, генерация, дополнение данных, сохранение. Искусственный процент больше не создаёт впечатление почти готового зависшего маршрута.
- Ограничено ожидание внешних запросов, динамического контекста и необязательных обогащений. Ошибка погоды/фото/обычного поиска не удерживает готовый маршрут. Обязательная проверка логистики закрытых аэропортов имеет отдельный таймаут и сообщает ошибку.
- Обогащения работают с копиями маршрута: операция, завершившаяся после таймаута, не меняет возвращённый результат. Отмена передаётся запросам моделей; при отмене не запускается резервная модель.
- Парсер принимает SSE Gemini и JSON DeepSeek, разрезанные UTF-8/CRLF пакеты, финальное событие без пустой строки, ошибки с кодами. При получении результата больше не ждёт закрытия потока.
- Сохранение не запрашивает повторно сессию и месячный AI-лимит. Раньше последняя разрешённая генерация могла завершиться, но не сохраниться из-за повторной проверки уже учтённого события.
- При ошибке сохранения маршрут открывается из локальной копии с предупреждением, без повторной генерации. Отмена предотвращает навигацию и создание локальной копии.

В браузере пройдены оба сценария планирования, получение результата SSE и имитация 503 при сохранении с открытием локального маршрута. Реальный восьмидневный маршрут Москва → Кейптаун с платной моделью повторно не запускался; качество ответа модели и фактическое время такого запроса этим тестом не подтверждены.

## Supabase, авторизация и консоль

- Proxy и OAuth callback проверяют пользователя через `getUser`, вместо доверия `getSession().user`. Для серверных запросов добавлены таймауты. Лишние чтения сессии на главной заменены общим AuthProvider.
- Контроль доступа использует серверную сводку и учитывает истечение временной блокировки. Убрана попытка браузера переписывать административные поля `profiles`.
- Ошибки обязательного чтения профиля/поездок дают 503, а не успешный ответ с пустыми данными. При ошибке сводки лимитов шапка сохраняет последнее подтверждённое значение.
- Повторные обращения к отсутствующему RPC ограничены паузой повторных попыток; предупреждение не печатается на каждом запросе. Добавлен SQL с атомарным счётчиком и доступом только service role: [20261014130000_request_rate_limits.sql](sql/20261014130000_request_rate_limits.sql).
- SQL **применён пользователем и проверен 14 октября, 22:52 МСК**. Под service role последовательные запросы при лимите 2 дали `true, true, false`; из 12 параллельных при лимите 5 разрешены ровно 5, заблокированы 7. Вызов под anon отклонён с `42501`. Два временных тестовых bucket удалены после проверки, пользовательские данные не затрагивались. [Результат проверки](supabase-rate-limit-verification-2026-10-14.json). Под authenticated вызов не выполнялся: отдельного тестового токена нет. SQL хранится в `docs/sql`, поскольку весь каталог `supabase/migrations` исключён текущим `.gitignore`.
- Добавлены описания диалогов и маркер smooth scroll для Next.js, убраны соответствующие предупреждения проверенных сценариев.
