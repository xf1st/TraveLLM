# Аудит профиля и настроек — 14 октября 2026

Область проверки: `/profile`, `/profile?tab=settings`, загрузка через `/api/user/me`, сохранение через `/api/user/profile`, использование настроек в коде. Это проверка конкретного пользовательского сценария, а не полный аудит Supabase/RLS или всех страниц сайта.

## Подключение к Supabase

- Настроены URL, публичный ключ и серверный service role. Значения ключей в отчёт и логи не выводились.
- Read-only запросы к `profiles`, `trips`, `trip_feedback` успешно выполнены: примерно 409, 384 и 382 мс соответственно в текущем окружении. Это единичные замеры доступности, не обещание скорости в production.
- Чтение профиля идёт через серверную сессию; запросы service role ограничиваются `user.id`. Изменения идут через PATCH с проверкой сессии, лимитом запросов, строгой схемой и allowlist полей. Прямого PATCH `profiles` из страницы профиля нет; аватар загружается через Supabase Storage.
- Схема колонок для сокращённого запроса поездок проверена read-only запросами без получения пользовательских строк. Миграции для этой задачи не требуются.
- Запись в настоящую базу, удаление аккаунта и загрузка файлов в Storage при проверке не выполнялись. Сценарии сохранения проверялись через отдельный локальный прокси с синтетическими данными и записью только в память.

## Найдено и исправлено

| Проблема | Изменение |
| --- | --- |
| Начальный render показывал «Путешественник», нули и значения предпочтений по умолчанию до ответа сервера | Анимированный скелетон повторяет шапку, статистику и карточки; поддерживает reduced motion и статус загрузки для скринридера |
| HTTP-ошибка могла считаться гостевым/пустым профилем; rejected fetch не имел обработки | Проверка ответа, отдельный экран ошибки, повтор запроса, отмена при уходе и таймаут 15 секунд |
| Ошибка чтения `profiles` или `trips` на сервере превращалась в успешный ответ с пустыми данными | Для обязательных данных возвращается 503; UI показывает ошибку вместо ложной статистики |
| Страница запрашивала все поля поездок и лишние данные лимитов/последних поездок | Явный список полей, исключены два ненужных запроса; в ответе остаются только локации завершённых маршрутов, нужные для статистики |
| Один `loading` использовался для чтения и сохранения | Состояния разделены; сохранение не заменяет профиль скелетоном |
| Переключатели менялись до подтверждения PATCH и оставались изменёнными при ошибке | Изменение после подтверждения сервера, индикатор сохранения, сериализация настроек приложения; отправляется только изменённый ключ preferences |
| Настройки были узкой вертикальной формой с маленькими чекбоксами и техническими заголовками | Карточки в стиле trip-glass, цветные иконки, пояснения, переключатели; две колонки на широком экране и одна на мобильном |
| На странице не было заявленного сброса подсказок | Добавлена отдельная кнопка сброса `travellm_hint_*` и `travellm_welcome_seen` |
| Загрузка аватара не обновляла остальные отображения профиля | Состояние профиля и событие `profile_updated` обновляются после успешного PATCH |

## Существующие ограничения для следующего этапа

1. `notifications_enabled` сохраняется, но в проверенном коде не найден потребитель этого флага для уведомлений о готовом маршруте. Сам переключатель не создаёт push/email-механизм.
2. `preferences.currency` сохраняется, но генерация бюджета сейчас выбирает RUB/USD по локали. Выбранная в настройках EUR не означает конвертацию бюджета. Переключение языка действительно меняет cookie и перезагружает интерфейс после сохранения.
3. Счётчик поездок включает локальные черновики из localStorage наряду с серверными поездками. Он не является чистым счётчиком строк Supabase; эту существующую семантику не меняли.
4. Страны рассчитываются эвристически из завершённых поездок и строк локаций. Разные написания одной страны могут давать отдельные элементы; нужна самостоятельная нормализация географии.
5. Общий layout содержит дополнительные запросы AuthProvider, header/sidebar и клиентских guards. Оптимизирован именно запрос страницы профиля; полного устранения всех дублирующихся запросов приложения эта задача не делает.

## Проверки

- Production build: `npm run build` проходит.
- TypeScript: `npm run typecheck` проходит.
- Unit tests: `npm test`, 16 тестов проходят, включая сохранение локаций после сокращения payload и обработку неполных маршрутов.
- ESLint изменённых файлов: без ошибок; в старой разметке профиля остаются предупреждения про `<img>` и кавычки.
- Браузер: загрузка с искусственной задержкой 10 секунд, 503 с повтором, успешный PATCH, отказ PATCH с сохранением прежнего значения.
- Мобильный сценарий: iframe 390 px (380 px полезной ширины со скроллбаром), `scrollWidth === clientWidth`; проверены расположение карточек и переключателей. Отдельный локальный тестовый прокси разрешал только same-origin iframe; production-настройки безопасности не менялись.
- RU и EN: новые строки внесены в оба словаря. Визуально проверена русская тёмная тема; остальные темы и английская длинная разметка не проверены в браузере.
