# Настройка админ-панели

## Шаг 1: Применить SQL миграцию

Выполните SQL миграцию в Supabase SQL Editor:

```bash
# Файл: supabase/migrations/add_admin_features.sql
```

Эта миграция создаст:
- Поля `role`, `access_mode`, `block_reason`, `blocked_until` в таблице `profiles`
- Таблицу `app_settings` для глобальных настроек
- Таблицу `admin_invites` для приглашений админов
- Таблицу `admin_audit_log` для аудита действий
- Исправит критическую дыру безопасности в RLS политиках `trips`

## Шаг 2: Назначить первого админа

После применения миграции, назначьте первого админа вручную:

```sql
-- Замените 'sergeifreddy@gmail.com' на email первого админа
UPDATE profiles 
SET role = 'admin' 
WHERE email = 'sergeifreddy@gmail.com';
```

## Шаг 3: Настроить поддомен (опционально)

Если хотите использовать `admin.travellm.ru`:

1. В DNS настройте CNAME запись для `admin.travellm.ru` → основной домен
2. В Timeweb App Platform добавьте дополнительный домен `admin.travellm.ru`
3. В Supabase Dashboard → Authentication → URL Configuration добавьте:
   - `https://admin.travellm.ru/auth/callback` в Redirect URLs

## Шаг 4: Доступ к админке

1. Войдите в систему с аккаунтом, которому назначена роль `admin`
2. Откройте `/admin` или `https://admin.travellm.ru`
3. Вы увидите дашборд с метриками

## Функции админки

### `/admin` - Дашборд
- Статистика пользователей и маршрутов
- Быстрые ссылки на разделы

### `/admin/users` - Управление пользователями
- Просмотр всех пользователей с поиском
- Блокировка пользователей:
  - **AI блокировка**: пользователь может просматривать маршруты, но не может генерировать новые
  - **Полная блокировка**: fullscreen экран "Доступ отключён"
- Приглашение новых админов по email

### `/admin/trips` - Все маршруты
- Просмотр всех маршрутов всех пользователей
- Поиск по названию, месту назначения, email пользователя
- Фильтрация по статусу (черновик/активен/завершён)

### `/admin/health` - Тестирование системы
- Проверка подключения к БД
- Проверка RLS политик
- Проверка Storage
- Проверка AI API (DeepSeek)
- Проверка Image API
- Проверка App Settings

### `/admin/settings` - Глобальные настройки
- **Тех. работы**: включение/выключение maintenance mode
- **AI провайдеры**: включение/выключение DeepSeek и OpenRouter
- **Лимиты**: максимальное количество генераций на пользователя в день

## Безопасность

- Все админские операции логируются в `admin_audit_log`
- RLS политики защищают данные: админы видят всё, пользователи только своё
- API роуты проверяют блокировки и maintenance mode
- Компоненты защиты (`AdminGuard`, `UserAccessGuard`, `MaintenanceGuard`) работают на клиенте и сервере

## Важные замечания

1. **Не храните пароли в коде** - все админы входят через Supabase Auth
2. **Первый админ назначается вручную** через SQL
3. **Дальнейшие админы** приглашаются через `/admin/users` → "Пригласить админа"
4. **Maintenance mode** блокирует всех, кроме админов (если включен bypass)
5. **Блокировки пользователей** проверяются на клиенте (UI) и сервере (API)

## Troubleshooting

### Админка не открывается
- Проверьте, что роль `admin` назначена в БД
- Проверьте, что вы залогинены
- Проверьте консоль браузера на ошибки

### RLS ошибки
- Убедитесь, что миграция применена полностью
- Проверьте, что политики созданы: `trips_admin_all`, `profiles_admin_all`

### Maintenance mode не работает
- Проверьте таблицу `app_settings` - должна быть одна строка
- Проверьте, что `maintenance_mode = true`
- Проверьте компонент `MaintenanceGuard` в `app/layout.tsx`
