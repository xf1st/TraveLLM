## 🏗️ Архитектура

### Сильные стороны ✅
- **Двойной AI с фолбэком** — Gemini → DeepSeek каскад обеспечивает аптайм
- **Валидация в реальном времени** через `validateRouteRequest()` перед генерацией
- **Динамическое обогащение контекста** — Google Search grounding + проверка рейсов
- **Санитизация аэропортов** — обнаруживает закрытые аэропорты, подменяет на поезд/автобус
- **Обогащение транспортных ссылок** — автоматическое IATA-разрешение + TravelPayouts
- **Управление подписками** — лимиты по тарифам через `checkGenerationLimit()`
- **Фильтрация контента** — FORBIDDEN_STEMS на сервере + защита от prompt injection
- **Режим обслуживания** — с обходом для админов
- **Блокировка пользователей** — `access_mode` с автоснятием `blocked_until`

### Проблемы ⚠️

#### 1. Огромное дублирование кода (КРИТИЧНО)
`deepseek/route.ts` (635 строк) и `gemini/route.ts` (1678+ строк) на ~80% идентичны:
- `enrichTransportLinks()` — скопирована 1:1
- `sanitizeClosedAirportLogistics()` — скопирована, **но с разной логикой!**
- `normalizeActivityTypes()` — скопирована
- `collectRealTimeSearchContext()` — скопирована
- Весь бойлерплейт POST-обработчика (авторизация, обслуживание, блокировка, лимиты) — дублирован

> [!CAUTION]
> Две функции `sanitizeClosedAirportLogistics()` **разошлись**. DeepSeek использует старый статический GROUNDING_DATA, а Gemini — новый `determineOptimalTransport()`. Одинаковые запросы **дают разные результаты** в зависимости от роута.

**Рекомендация:** Извлечь общую логику в `lib/route-pipeline.ts` с параметризацией по AI-движку.

#### 2. Злоупотребление типом `any`
Оба API-роута используют `any` повсюду:
- `routeData: any` — основной объект ответа без типизации
- `day.activities` — нетипизированный массив
- `act: any` — объекты активностей без типов
- `GROUNDING_DATA_2026 as any` — приведение к any

**Рекомендация:** Определить интерфейсы `ItineraryDay`, `Activity`, `RouteData`, `Logistics`.

#### 3. Пробелы в обработке ошибок
```typescript
// deepseek/route.ts строка 581
} catch (e) {} // Тихое проглатывание — без логирования

// gemini/route.ts строка 132
} catch (e) {} // Тихое проглатывание
```
Пустые catch-блоки скрывают ошибки сбора динамического контекста и генерации ссылок.

#### 4. Утечка `error.message` клиенту
```typescript
// deepseek/route.ts строка 632
return NextResponse.json({ error: error.message }, { status: 500 })
```
Стектрейсы и внутренние ошибки утекают клиенту в продакшне.

## 🔒 Анализ безопасности

### ✅ Хорошие практики
- Серверная фильтрация FORBIDDEN_STEMS (русский мат + prompt injection)
- Санитизация строк: `safeHighlight` убирает кавычки, обрезает до 300 символов
- Фолбэк-цепочка Supabase service role key
- Контроль доступа пользователей (blocked/ai_blocked/full_blocked)
- Middleware с проверкой авторизации по путям

### ⚠️ Уязвимости

| # | Серьёзность | Проблема | Расположение |
|---|---|---|---|
| 1 | 🔴 ВЫСОКАЯ | `SUPABASE_SERVICE_ROLE_KEY` в API-роутах через `createClient()` — даёт админ-доступ к БД | Оба роута |
| 2 | 🟡 СРЕДНЯЯ | Нет rate limiting на API-роутах помимо подписных лимитов — возможен DoS | Все API |
| 3 | 🟡 СРЕДНЯЯ | `customBudget` парсится через `parseInt(customBudget.replace(/\D/g, ''))` — без верхнего лимита | Оба роута |
| 4 | 🟡 СРЕДНЯЯ | `customDestination` сплитится по `;` и вставляется в промпт — потенциальная инъекция | Оба роута |
| 5 | 🟠 НИЗКАЯ | Защита от prompt injection на статическом списке; продвинутые техники (Unicode, кодирование) обходят | Оба роута |
| 6 | 🟠 НИЗКАЯ | `console.error`/`console.log` — PII может утекать в логи | Везде |

### Рекомендация
Использовать Supabase-клиент с anon key и RLS для чтения пользовательских данных. Service role key — только для админских операций.

## 🧠 Анализ промпт-инжиниринга

### Структура
Многослойная система промптов:
1. **`strict-rules.ts`** — 1000+ строк правил с `ITINERARY_STRUCTURE`
2. **`prompt-builder.ts`** — 500+ строк конструктора промпта
3. **Системный промпт в роуте** — инлайн в обоих API
4. **Динамический контекст** — реалтайм Google Search + данные рейсов
5. **Grounding data** — статический `GROUNDING_DATA_2026` для закрытых аэропортов

### Качество ✅
- Правила исчерпывающие и хорошо структурированы
- Бюджетные ограничения прописаны с подневным расчётом
- Сезонность встроена в промпты
- Россия-специфичные правила детальные

### Проблемы ⚠️
- **Три разных пути построения промпта** — `prompt-builder.ts`, инлайн в `deepseek/route.ts`, инлайн в `gemini/route.ts`. Дают **разные промпты** для одного и того же запроса
- Gemini-роут имеет ~100 строк дополнительной кастомизации промпта
- Россия-специфичные правила есть только в Gemini (строки 733-747), в DeepSeek отсутствуют
